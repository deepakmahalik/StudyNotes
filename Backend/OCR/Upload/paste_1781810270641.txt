
### 1. Traditional Evaluation Metrics (0:30 - 5:10)
These metrics are designed for fixed reference answers, primarily measuring text overlap:
* **BLEU (Bilingual Evaluation Understudy):** Measures *n-gram* overlap between generated and reference text. Includes a *brevity penalty* to discourage overly short answers (0:32 - 2:08).
* **ROUGE (Recall-Oriented Understudy for Gisting Evaluation):** Focuses on *recall*—how much of the core information in the reference is present in the output. Ideal for summarization (2:09 - 3:35).
* **F1 Score:** The harmonic mean of precision and recall. It is highly effective for tasks where specific facts or entities are the priority, rather than word-for-word phrasing (3:36 - 5:09).

### 2. The Need for RAG-Specific Metrics (5:10 - 6:00)
RAG systems operate in two stages: **retrieval** and **generation**. Because RAG relies on external context to generate answers, traditional metrics fail to measure the quality of these specific stages.

### 3. Key RAG Evaluation Metrics (6:07 - 9:19)
To evaluate RAG effectively, we look at both how well the system finds information and how well it synthesizes it:
* **Context Precision:** Measures how much of the retrieved information is actually relevant to the user query (how much extra added)
* **Context Recall:** Measures the retriever’s ability to pull *all* necessary information from the database (How much information missed).
* **Answer Relevance:** Uses embeddings to assess if the generated answer directly addresses the user's intent (7:34 - 8:06).
* **Faithfulness:** Ensures the answer is strictly grounded in the retrieved context, preventing hallucinations (8:07 - 8:39).
* **Groundedness:** Evaluates if the answer relies on the retrieved documents rather than the model's internal memory (8:40 - 9:19).

### 4. Modern Evaluation Workflow (9:20 - 12:19)
* **LLM-as-a-Judge:** Since calculating metrics like faithfulness requires semantic understanding, developers use a large language model to act as an evaluator, mimicking human judgment (9:20 - 10:16).
* **RAGAS (RAG Assessment):** This open-source framework standardizes the evaluation pipeline. It automates the calculation of context precision, context recall, faithfulness, and answer relevance using a combination of embeddings and LLM-based scoring (10:17 - 12:19).
